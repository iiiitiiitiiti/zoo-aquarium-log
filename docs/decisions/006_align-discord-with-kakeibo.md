## 006. Discord へ送る仕組みと書き換えを、かけいぼの版にそろえる

- 日付: 2026-11-25
- 対象: `.github/notify-discord.sh`・`.github/workflows/edit-discord.yml`（新しく足した）・`deploy-pages.yml` の `notify`。消したのは `.github/edit-discord-post.sh` と `edit-discord-post.yml`

### 決定

2026-11-25 に本人が「かけいぼ版にそろえる」と決めた（メイン経由）。`notify-discord.sh` はかけいぼのコミット 226fb93 の中身をそのまま写した。書き換えの流れも同じコミットの `edit-discord.yml` を写し、ツールの名前（`APP_NAME`）だけを変えた。005 で作った書き換えの作りは消した。

書き換えは次のコマンドで行う。`message` は `last`（最後に送った投稿）か Discord の投稿リンク。`notes` には書き換えた後の変わった点を1行に1つ書く。前の文は引き継がないので、残す行もすべて書く。見出しと末尾の「開き直すと新しい版になります」は自動で付く。

```bash
gh workflow run edit-discord.yml -R iiiitiiitiiti/zoo-aquarium-log -f message=last -f notes="1行目
2行目" -f dry_run=true
```

本人が投稿のリンクを貼るか「最後の投稿を直して」と言ったら、Claude は次の順で進める。

1. 直した文を akapen スキルに通す
2. `dry_run=true` で流れを動かし、ログで今の文と書き換えた後の中身を見る
3. 本人に見せて承認を得る（人に届く操作なので）
4. `dry_run` を外して流れを動かす

### 背景

同じ日に、かいもの・かけいぼ・動物園・水族館ログの3つの窓口が、それぞれ別の作りで書き換えを入れた。004 では3つの `notify-discord.sh` を同じ中身にすると決めていたので、中身がばらばらになった。メインがどれにそろえるかを本人に尋ね、本人がかけいぼ版を選んだ。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| 動物園・水族館ログの版（005）を残す | 本人がかけいぼ版を選んだ。005 の版は本文の全文を差し替える作りで、見出しの書式を毎回書く手間がある |
| 送る手順だけそろえ、書き換えは別のまま残す | 3つのリポで直し方が違うままになり、窓口ごとに手順を覚え直すことになる |

### 影響範囲

- 005 の版になく、かけいぼ版にだけある安全策が入った。書き換える前に投稿の今の文をログに出す。番号を残す手順が失敗しても公開は成功にする（`continue-on-error`）。送り先の URL の末尾の `/` と `?thread_id=` を分けてから付け直す。
- 番号を残す成果物の名前は `discord-post` から `discord-message` に変わった。前の名前で残した番号は無い（この時点でお知らせを1回も送っていない）。
- 書き換えの入力が、本文の全文（005）から変わった点の行だけになった。手順書やメモの古いコマンドは使えない。
- `notify-discord.sh` はかけいぼと同じ中身になった。直すときは、かいもの・かけいぼと3つそろえる（004）。
- 2026-11-27 にかけいぼの f336b86 を写した。最後の補足に「前のままなら、何度か開き直してください」の1行が付く（書き換えの投稿にも付く）。

### 検証

- 2026-11-25 に、Discord の代わりをする手元の受け口で次を確かめた。
  - お知らせの行が無ければ送らない。
  - 送ると `?wait=true&thread_id=` で送り、返った番号をファイルに残す。
  - `last` の dry_run で今の文と書き換えた後の中身を出す。行頭の「- 」と CRLF は整える。
  - リンク（末尾の `?` つき）で今の文を読んでから書き換える。読むとき・書き換えるときの両方で `?thread_id=` を付ける。
  - 止まる場合も確かめた。無い投稿・last の記録なし・空の文・送り先が空の4つである。
- 同じ日に GitHub の上で `edit-discord.yml` を `dry_run=true` で2回動かした。
  - `last` は「最後に送った投稿の記録が見つかりません」で止まった。まだ1回も送っていないので正しい。
  - 無い番号のリンクは「書き換える投稿が見つかりません」で止まった。シークレットの送り先へ読みに行けている。
  - この変更の公開（e0c93d3）は notify まで成功した。お知らせの行が無いので送っていない。
- `last` で成果物から番号を読む流れは、最初のお知らせを送るまで未検証。かけいぼでは本物のリポで確かめてある（かけいぼの 006）。
