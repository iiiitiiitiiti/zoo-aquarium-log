## 005. 送った更新のお知らせは、手で動かす GitHub の流れで書き換える

- 日付: 2026-11-25
- 対象: `.github/workflows/edit-discord-post.yml`・`.github/edit-discord-post.sh`・`.github/notify-discord.sh`・`deploy-pages.yml` の `notify`

### 決定

Discord へ送ったお知らせ（004）を、あとから書き換えられるようにした。送るときに `wait=true` で投稿の番号を受け取り、公開の記録（Actions の artifact `discord-post`）に90日残す。書き換えは手で動かす流れ `edit-discord-post.yml` で行う。入力は投稿のリンクか番号（空なら最後に残した番号）と新しい本文の全文で、本文が空なら今の本文を出すだけにする。

本人が投稿のリンクを貼るか「最後の投稿を直して」と言ったら、Claude は次の順で進める。

1. 本文を空にして流れを動かし、ログから今の本文を読む
2. 直した本文を akapen スキルに通してから、本人に見せて承認を得る（人に届く操作なので。akapen に通すのは同日の本人の依頼で、送るときも同じ）
3. 本文を入れて流れを動かし、ログで書き換え後の本文を確かめる

```bash
gh workflow run edit-discord-post.yml -R iiiitiiitiiti/zoo-aquarium-log -f message=<リンク。最後なら空> -f content=<新しい本文>
```

### 背景

2026-11-25 に本人から、前に送った投稿をあとから書き換えたいと頼まれた。先にふたりのレシピ帳（Artifact）が、送るたびに投稿の番号を残し、ウェブフックの「投稿の編集」で書き換える形を入れていた。動物園・水族館ログの送り先は GitHub のシークレットにしか無く、手元の Claude は読めない。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| 手元から書き換える | 送り先の URL を手元やチャットに置くことになる。004 で「リポ・記録・チャットに書かない」と決めている |
| 投稿の番号をリポのファイルに書いてコミットする | 公開のたびに CI が main へ push することになり、その push でまた公開が走る。手元の clone も毎回古くなる |
| 番号を残さず、毎回リンクを貼ってもらう | 「最後の投稿を直して」が言えなくなる |
| 書き換えも notify ジョブの中で行う | 公開のたびにしか動かせない。直したいのは公開と関係ないときが多い |

### 影響範囲

- 書き換えられるのは、このリポのウェブフックが送った投稿だけ（Discord の決まり）。別のツールの投稿や人の投稿は 404 で止まる
- 「最後の投稿」は、最後に番号を残した公開の投稿を指す。番号を残すのは90日までである。それより古い投稿と、この仕組みを入れる前の投稿は、リンクを渡して直す
- 本文は全文を差し替える。2000字を超えたら書き換えずに止める。メンションは無効にする
- ウェブフックの URL に `?thread_id=` が付いていれば、書き換えにも付ける
- `notify-discord.sh` は、かいもの・かけいぼと同じ中身だった。同じ日に、かいもの（`discord-edit.yml`）とかけいぼ（`edit-discord.yml`）の窓口も、それぞれ別の作りで書き換えを入れた。今では3つの `notify-discord.sh` の中身が違う。そろえるかは Windows のメインに預けてある

### 検証

2026-11-25 に、Discord の代わりをする手元のサーバーで次を確かめた。

- 送ると番号が返り、ファイルに残る。お知らせが無ければ送らず、番号も残さない
- URL に `?` があれば `&wait=true` を付けて送る。`?thread_id=` は書き換えにも付ける
- リンク（末尾の `/` や `?` つきを含む）か番号で今の本文を読める。書き換えて読み直すと変わっている
- 止まる場合: 番号でない入力、無い投稿（404）、2001字（2000字は通る）、送り先が空、最後の番号の記録が無い（本物のリポに問い合わせた）

同じ日に GitHub の上でも流れを動かした。無い番号を読ませると Discord が「Unknown Message」と返したので、シークレットの送り先のウェブフックは正しい（送り先が違えば「Unknown Webhook」と返る）。番号を空にすると「記録がありません」で止まった。お知らせの行が無い公開では送らず、artifact も作らなかった。artifact に残した番号を読む流れは、最初のお知らせを送るまで未検証。
